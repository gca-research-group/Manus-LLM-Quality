Write code in Java 5 for the following system, use only the standard Java library. The system must be able to compile and run in the Eclipse 3.1 IDE. Do not use features introduced after Java 5. Do not comment on the code. The system must use object oriented design. The system must be executable and, as such, must contain a main class. For the sake of testing, outputs must be displayed in the console.

The system is backend only, and it aims to compute the order totals for a small store. The system also manages catalog and stock, registers customers and suppliers, manages carts, assembles orders, applies promotions and shipping rules, registers payments, processes returns and refunds, processes restocking operations, records cashflow, and generates basic reports. The system has no graphical user interface and no external integrations.

The system will run in a single process and will store all working data only in memory using collections. The system may write CSV files using only the standard Java library, but only for inventory and cashflow operations.

The returned project must compile as written, without requiring any manual edits.

The project must be divided into Java packages. Choose a coherent package structure appropriate to the system. Do not put all classes in a single package. Every file must begin with a package declaration that exactly matches its file path. All imports and package declarations must be internally consistent.

No class may directly access the private fields of another class. If one part of the system needs information from another part, it must use methods such as getters or business operations rather than illegal direct field access. The returned code must compile without changing field visibility manually after generation.

The system must obey the following business rules:
- Product identifiers are unique.
- Customer identifiers are unique.
- Supplier identifiers are unique.
- Unit prices, shipping values, discount values, payment values, refund values and restock unit costs cannot be negative.
- Stock quantities cannot become negative.
- Cart item quantities must be positive.
- Restock quantities must be positive.
- Inactive products cannot be added to carts.
- Each order must contain at least one order item.
- The subtotal of an order is the sum of the subtotals of its order items.
- The subtotal of an order item is given by its quantity multiplied by the unit price stored in that order item.
- The final total of an order is given by: subtotal minus promotion discount plus shipping.
- Cancelled orders cannot be paid.
- Paid orders cannot be cancelled.
- If an unpaid order is cancelled, the stock reserved by that order must be restored.
- Only paid orders can be returned.
- A return must contain at least one returned item.
- The returned quantity of a product cannot exceed the quantity originally bought in that order.
- A successful payment must generate a cash inflow entry.
- A successful refund must generate a cash outflow entry.
- A successful return must restore the returned stock quantity.
- A successful restock must increase stock quantity and generate a cash outflow entry.
- If an operation would violate any of these rules, it must be rejected.
